# Setup — Getting This Running in Xcode

This repo contains hand-written Swift source files, organized to match a
real Xcode project, but not yet an actual `.xcodeproj`. Xcode project files
are safest generated by Xcode itself rather than hand-authored, so step one
is a quick wizard, then dropping these files in.

## 1. Install Xcode
If the Mac App Store won't offer Xcode because your macOS is older than the
latest release requires, download a matching older Xcode version instead
from **developer.apple.com/download/all/** (sign in with any Apple ID, no
paid enrollment needed). Match the Xcode major version to your macOS
version's era — e.g. Xcode 16.x for macOS Sequoia (15.x).

## 2. Create the project shell
1. Xcode → File → New → Project
2. **iOS → App**
3. Product Name: `HoldMeUp`
4. Interface: **SwiftUI**
5. Language: **Swift**
6. Storage: **None**
7. Set **Minimum Deployments** to **iOS 17**
8. Save it somewhere temporary (e.g. Desktop) — you'll bring the real source
   files in next.

## 3. Bring in the source files
1. Delete the placeholder `ContentView.swift` Xcode generated.
2. In Finder, drag the entire `HoldMeUp/` folder from this repo into the
   Xcode project navigator (drop it inside the blue project icon). Choose
   **"Copy items if needed"** and **"Create groups."**
3. This brings in `HoldMeUpApp.swift` too — when Xcode flags the
   duplicate/conflicting file, keep the one from this repo, not Xcode's
   auto-generated one.
4. Build (⌘B). If you get "Cannot find type X in scope" errors, a file
   probably didn't get added to the app target — select it in the
   navigator, open the File Inspector (right panel), and make sure
   "HoldMeUp" is checked under Target Membership.

## 4. Add required Info.plist entries (for MultipeerConnectivity)
Select the project in the navigator → your target → **Info** tab → add:
- `NSLocalNetworkUsageDescription` (String) — e.g. *"Hold Me Up uses your
  local network to connect nearby players for multiplayer games."*
- `NSBonjourServices` (Array of Strings), two entries:
  - `_holdmeup._tcp`
  - `_holdmeup._udp`

Without these, MultipeerConnectivity silently fails to discover/advertise
on iOS 14+.

(No entry is needed for CoreMotion/the gyroscope — `NSMotionUsageDescription`
only applies to step-counting/activity APIs, not raw device motion.)

## 5. Run it
- Simulator works fine for Onboarding, Home, How to Play, and Support
  screens.
- **Host/Join/Gameplay need real devices** — Simulator can't fake nearby
  peer discovery or real gyroscope data. Test with two physical iPhones once
  you're at that stage.
- Sign in under Xcode → Settings → Accounts if you haven't — creates a free
  "Personal Team," enough to run on your own device before formal Developer
  Program enrollment.

## 6. Suggested build order
1. Onboarding + Home (Simulator is fine)
2. How to Play tutorial (Simulator is fine — static/sample data)
3. Host/Join/Lobby (needs 2 physical devices)
4. Gameplay + Results (needs 2 physical devices)
5. Support & Unlocks — real purchases need Developer Program enrollment +
   App Store Connect product setup first; the UI can be reviewed before that
